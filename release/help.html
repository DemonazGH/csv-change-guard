Start with the synthetic demo

  1. On Windows, right-click the downloaded ZIP and choose Extract All. Open the extracted CSV-Change-Guard folder. Keep the folder's contents together; do not run inside the ZIP preview.
  2. Open the dist folder, right-click index.html, and choose Open with → Google Chrome or Microsoft Edge. No installation, account, build, or internet connection is needed for this local-file workflow.
  3. Click Try the built-in demo. It sets the price threshold to 30% and the assumed overwrite setting to enabled, then compares synthetic data.
  4. Review the verdict, counts, findings, and coverage. The deliberately risky demo should match the table below.
  5. Click Save HTML report and open the download in Chrome or Edge. Close the app tab and confirm the report still makes sense on its own.

All supplied catalogs are synthetic. Do not import these samples into a real store. CSV Change Guard only compares files; it never performs an import.

Choose files and settings

  1. Open the app and click Clear files if a previous comparison is loaded.
  2. Under Current catalog, select your trusted baseline. For a synthetic practice run, choose samples/current-catalog.csv from the extracted folder.
  3. Under Proposed update, select the file to review. For the same practice run, choose samples/proposed-update.csv.
  4. Check both displayed filenames. Confirm the price threshold and the assumed Shopify import setting, then click Compare files.

With the supplied practice pair, a 30% threshold and overwrite enabled, the results match the demo above. To try an unchanged comparison, use samples/unchanged-update.csv as the proposed update. Image-coverage warnings remain because images are outside the comparison.

Price threshold

The default 30% flags price increases and decreases of at least 30% for priority review. Smaller valid price changes are still reported. A threshold is a review preference, not a rule that makes a price safe. Changing a setting hides the previous report: click Compare files again to generate results with the new setting.

Overwrite assumption

Overwrite matching handles: enabled allows the report to compare supported changes for existing handles. With disabled, existing-handle update records are ignored for change comparison and disclosed in coverage. The app does not know which handles currently exist in a live store. This setting changes the report only; it does not read or change your Shopify settings.

Use files from the same store and currency. The app does not infer currency or convert amounts. Keep your original files and an appropriate backup. Test any actual import separately in an authorized, controlled workflow.

Read the whole report

Begin with the verdict and Coverage, matching rules, and limitations. Check the filenames, threshold, overwrite assumption, excluded rows, recognized columns, and limitations before drawing conclusions from a count.

What the finding levels mean
LevelHow to use it
BlockingPart of the input could not be reliably assessed, or a selected structural issue was found. The comparison may be incomplete. This does not claim Shopify will reject the file.
HighA potentially consequential change needs review, such as a threshold price movement, zero price, explicit clearing, or changed option value.
WarningReview a coverage gap, unmatched update record, selected inconsistency, or visibility change.
InfoAn ordinary change or scope detail, such as a baseline variant absent from a partial update.

Priority findings adds blocking and high findings. Compared variants counts exact matched variant pairs; it does not count all source rows. Unpaired update rows identifies update rows without a usable exact pair. Findings can overlap on the same record.

Use the severity buttons and search box to inspect findings. Next and Previous move through pages of up to 40 findings. A search with no matches means the current view is empty; it does not mean the comparison passed. Long before/after values may be shortened in the app; exports contain the full values.

Record references count the header as record 1. A quoted value spanning several text lines remains one CSV record.

An absent row is not a deletion prediction. An omitted column is unassessed, not an explicitly cleared value. No findings is not import approval.

Save a report, then clear the workspace

  • Save HTML report downloads a readable, standalone report with findings, settings, filenames, coverage, and limitations. Open it in a browser without the app. Use the browser's Print command if you need paper or a PDF; review the print preview first. On narrow screens, scroll the findings table sideways to reach every column.
  • Export findings CSV downloads findings for spreadsheet viewing. Formula-like cells are prefixed with an apostrophe as a viewing precaution. This is a findings report, not an import-ready product CSV.
  • JSON downloads the structured report and preserves original strings. It is intended for inspection or further technical analysis.

Every export includes all findings, regardless of the current filter, search, or page. The browser controls the download location, usually Downloads. Later downloads may receive a numbered filename; check that you opened the new report.

Click Clear files to remove both loaded filenames and visible results, disable Compare files, and clear search and report state. Your threshold and overwrite setting remain selected. The built-in demo restores its default settings.

Clear files does not delete the original CSVs or any downloaded HTML, CSV, JSON, or PDF reports. It removes loaded data from application state and the page; browser memory is managed by the browser and secure erasure is not guaranteed.

Supported scope and limits

  • Format: UTF-8, comma-delimited CSV, including quoted commas, escaped quotes, and multiline fields. XLSX files, semicolon-delimited files, and arbitrary supplier schemas are not supported.
  • Required columns: recognized handle, Title, and SKU columns in both files. Selected current and legacy Shopify header names are recognized. Complete supported variant data should include Option1 name/value.
  • Identity: exact, case-sensitive handle plus non-empty SKU. This is this tool's comparison key, not a claim about Shopify importer identity rules. Missing or duplicate keys make matching incomplete. Changed handles or SKUs are not inferred from row order or fuzzy similarity.
  • Per-file limits: 5,000 data records, 10 MiB, and 200 columns. Image-only continuation records count toward the input record limit even though images are unassessed. These are the tool's limits, not Shopify platform limits.
  • Prices: non-negative dot-decimal values, with up to 12 integer digits and 6 decimal places. Currency symbols, locale guessing, negative prices, and scientific notation are unsupported. Threshold comparisons use exact decimal arithmetic; displayed percentages are truncated to two decimal places.
  • Checks: supported price changes, selected malformed prices, explicit blanks in selected fields, selected option/visibility changes, and missing/ambiguous identifier diagnostics. Only supported columns present in both files are compared.
  • Product and continuation rows: product fields come from the first row for a handle. Blank later option names can use a clear first-row option name within the same input; option values are never inherited. Image-only continuation records are excluded from variant comparison.

Unassessed: images, inventory, taxes, shipping, market-specific prices, metafields, unrecognized columns, and comprehensive Shopify schema rules, dependencies, defaults, or option combinations. The app does not simulate Shopify's importer, make a backup, fix source files, or verify live-store state.

The tool is an independent review aid. It is not affiliated with or certified by Shopify. Matching counts and zero price changes do not establish that an import is safe.

Your files stay on your computer

The application reads selected files in browser memory and generates local downloads. This build has no CSV uploads, store connection, telemetry, tracking, external fonts or scripts, cookies, or local-storage persistence. No model or API processes your catalog. The optional localhost server serves the static app and accepts no file uploads.

Original files and downloaded reports remain wherever you saved them. Reports may contain sensitive product identifiers, filenames, and before/after business values. Decide who can access them before sharing, backing them up, printing, or storing them in a shared folder.

The browser, extensions, operating system, cloud-synced folders, filesystem backups, and other software have their own access and retention behavior. The app's local processing does not control those systems.

Do not send merchant CSVs, exported reports, or unredacted screenshots to support, a public repository, or an AI workspace. Reproduce problems with the supplied synthetic samples wherever possible.

Troubleshooting

The file opens as text, or the app will not open

Confirm the ZIP is fully extracted. Right-click dist/index.html and use Open with to select Chrome or Edge. If a managed browser blocks local HTML, keep security settings and sandboxing enabled. Ask your administrator about the policy or use the optional localhost route below if permitted.

Optional localhost route

If Node.js is already installed, open PowerShell in the extracted CSV-Change-Guard folder and run:

node server.cjs

Open the http://127.0.0.1:... address printed in the terminal. Leave the terminal open while using the app. Press Ctrl+C to stop it afterwards. No dependency installation is required. This route needs Node.js; the normal direct-file route does not.

If the server reports that its port is already in use, use the working direct-file route or record the error for review. Do not terminate an unfamiliar process or disable browser protections to make the test pass. The server serves only the app; open this help file directly from the extracted folder.

Compare files is disabled

Select both a current catalog and a proposed update, and wait for reading to finish. Check the displayed filenames. If a file failed to load, read the error message and select a valid file again. Clear files intentionally disables comparison until two files are selected.

An encoding, header, or input-limit error appears

Use a UTF-8, comma-delimited CSV with recognized required columns and within the limits above. A filename ending in .csv does not establish the format. Keep the original, and avoid spreadsheet changes that silently alter identifiers, encoding, or decimal notation. Test with the included samples before changing a real workflow.

An unchanged file still has warnings

Coverage warnings describe what the app did not assess, such as images or unsupported columns. They can appear with identical files and zero price changes. Read coverage rather than treating the warnings as proof of a changed catalog.

There are fewer comparisons than expected

Check missing/duplicate identifiers, unpaired update rows, excluded image-only rows, and the overwrite assumption. A changed SKU or handle cannot be paired by guessing. An incomplete comparison is a reason to investigate the unassessed rows.

The report seems old, or the download is missing

Use the browser's Downloads list to find the latest file. Check its filenames and settings. Browser-managed download restrictions may need administrator help. Do not disable protections. For long tables on small screens, scroll horizontally and review full values in the export.

Can the report make changes in Shopify?

No. It cannot connect to a store or perform an import. Findings CSV and JSON exports are reports, not corrected product-update files. You remain responsible for reviewing changes and separately validating the actual import workflow.
