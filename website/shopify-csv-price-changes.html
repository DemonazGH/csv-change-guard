Shopify CSV review guide

Review price changes.
Before importing.

A proposed price of 5.90 can look reasonable in a spreadsheet. Seeing it beside the current 59.00 makes the 90% drop easier to question. Here is a practical way to review a Shopify product CSV update, including the rows a comparison cannot assess.

Keep the current export as your baseline

Save a dated, unedited copy of the current catalog. Prepare the proposed update as a separate file. Use files from the same store and currency, and confirm which is the baseline before comparing. CSV Change Guard does not infer currency or check whether your baseline still matches the live store.

Keep the variant information and relevant columns together while editing. A price update can also contain an accidental blank description or changed option value. Shopify documents dependencies between CSV columns, including variant option fields, so removing columns needs care. Shopify product CSV format and dependencies.

For the downloadable prototype, both files need recognized handle, title and SKU columns. Use UTF-8 comma-delimited CSV and supported non-negative dot-decimal prices without currency symbols. Current limits are 5,000 data records, 10 MiB and 200 columns per file. These are this tool’s limits.

Check which variant is being compared

CSV Change Guard pairs variants using an exact, case-sensitive handle and non-empty SKU. For example, desk-lamp / LAMP-001 must identify one eligible variant in each file. This is the tool’s comparison rule. Shopify’s importer has its own rules.

A changed SKU, missing identifier or duplicate pair can leave a row unmatched or excluded. Check those findings before interpreting the price count. The tool does not recover a match from row order or a similar product name.

Review the direction and size of each change

The public trial uses a 30% price-movement threshold. Increases and decreases of at least that amount receive high-priority findings. Smaller changes still appear. The downloadable utility lets you choose the threshold.

Ask whether each change matches the intended pricing plan. The lamp’s drop could be deliberate or a misplaced decimal. The zero-priced bag needs a separate check. Percentage movement from an old price of zero is undefined, so inspect the actual values in that case. Displayed percentages are truncated to two decimal places.

Resolve the gaps behind the totals

The synthetic trial compares four variants and finds four price changes. Its verdict is still “Incomplete comparison — blockers need review” because other rows cannot be reliably paired. Four compared variants do not establish complete coverage of either file.

Keep three situations distinct. An explicit blank in a supported field can create a clearing finding. An omitted column is unassessed. A baseline row absent from the proposed update is informational and does not predict deletion.

Confirm the report’s overwrite assumption too. Shopify explains how its matching-handle overwrite option affects imports and how blank cells and omitted columns can behave differently, with dependencies that need separate review. Shopify overwrite and import guidance.

Keep the report with the reviewed versions

Save the standalone HTML report and check its filenames, threshold, overwrite assumption and limitations. It includes all findings, even if the screen is filtered. After editing the proposed CSV, compare again so the saved report describes that version.

Images, inventory, taxes, shipping, market-specific prices and metafields remain outside this comparison. Zero findings is not approval to import. Maintain an appropriate backup and test the actual import workflow separately. Shopify also recommends backing up product data before importing. Shopify preparation guidance.
